# Documentation Update Summary

This document summarizes the code and documentation changes made to reflect updates to the Lambda throttling remediation logic.

## Core Changes

### Code & Contract Updates
- **Safety buffer multiplier**: Raised from `1.10` to `1.25`
- **Minimum floor**: Raised from `5` to `10`
- **Rationale**: Stronger safety margin for traffic variance and more conservative baseline protection
- **Implementation fix**: Added `math.ceil()` and `max()` logic to ensure the function returns an integer and enforces the documented floor, matching the test contract

### Test Contract
- All 11 tests in `tests/test_lambda_scaling.py` now pass, validating:
  - Integer return type (AWS API requirement)
  - Minimum floor enforcement (10)
  - Safety buffer application (1.25x)
  - Validation of negative inputs

## Documentation Files Updated

### 1. `docs/lambda-throttling.md`
- **Example output**: Updated calculation from `44 (max(5, ceil(40 * 1.10)))` to `50 (max(10, ceil(40 * 1.25)))`
- **Section "Why a 1.25 safety buffer?"**: 
  - Clarified that traffic bursts to ~1.25x average are common
  - Notes the stronger safety margin compared to the previous 1.10x multiplier
- **Section "Why a floor of 10?"**: 
  - Explains that the floor of 10 (vs. 5 previously) is conservative enough for traffic variance scenarios

### 2. `docs/remediation-playbooks.md`
- **Recommendation logic section**: 
  - Updated minimum floor reference from `5` to `10`
  - Updated safety multiplier reference from `1.10` to `1.25`
  - Preserved contract explanation ensuring recommendations never fall below observed load

### 3. `AGENTS.md` (Reference only)
- Correctly documents the Remediation Contract pointing to code/test constants as authoritative

## Impact
These changes ensure operators understand and rely on more conservative recommendations generated by the updated remediation logic. The 1.25x safety buffer and floor of 10 provide improved protection against traffic spikes and throttling incidents in production environments.
